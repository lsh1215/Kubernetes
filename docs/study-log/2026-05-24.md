## Meaningful Questions

### Docker Compose에서 왜 `ports`가 필요한가?

Docker/Compose 기본 모델에서는 컨테이너가 network namespace 단위다. 컨테이너 안에서 `0.0.0.0:80`에 프로세스가 떠 있어도 그것은 컨테이너 network namespace의 80번 포트다. 호스트에서 접근하려면 `-p 8080:80` 또는 Compose `ports: ["8080:80"]`로 host port를 container port에 publish해야 한다.

### `0.0.0.0:<hostPort>`는 무슨 뜻인가?

`0.0.0.0`은 클라이언트가 목적지로 쓰는 주소라기보다 서버가 모든 네트워크 인터페이스에 bind한다는 의미다. Docker port publishing에서 host가 `0.0.0.0:8080`을 listen하면 `localhost:8080`이나 `<host-ip>:8080`으로 접근할 수 있다.

### namespace의 `name`은 무엇인가?

namespace의 `name`은 사람이 붙인 문자열만 뜻하지 않는다. PID, UID, 파일 경로, hostname, 인터페이스 이름, IP/port 같은 식별자가 어떤 실제 커널 자원을 가리키는지 결정하는 범위를 뜻한다.

### namespace 영속화는 무엇인가?

namespace는 디스크에 저장되는 파일이 아니라 커널 객체다. 빈 파일은 namespace 데이터를 담는 저장소가 아니라 namespace 참조를 bind mount로 붙잡아둘 경로다. 이 참조가 있으면 프로세스가 종료된 뒤에도 `nsenter`나 `ip netns exec`로 같은 namespace에 다시 들어갈 수 있다.

## Key Takeaways

- 컨테이너는 VM이 아니라 Linux 커널 기능을 조합한 프로세스 실행 환경이다.
- namespace는 프로세스의 view를 분리한다.
- cgroup은 프로세스 그룹의 자원 사용량을 제한하고 측정한다.
- chroot는 root filesystem 전환 아이디어를 제공하지만, 단독으로는 컨테이너가 되기에 부족하다.
- OverlayFS/union mount는 이미지 레이어와 writable layer를 하나의 filesystem처럼 보이게 만든다.
- Docker 기본 모델에서는 container가 network namespace 단위이고, Kubernetes에서는 Pod가 network namespace 단위다.
